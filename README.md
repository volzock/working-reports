## 1. Как устроена LLM и как её развернуть

**Файл:** `llm-inner-intro.pdf` · внутренний тех-доклад

Разбор устройства современной LLM на двух открытых моделях: **IBM Granite 4.1 3B** как чистая
классика (dense decoder-only) и **Qwen3.8-27B** как современный гибрид — от карточки на
Hugging Face до продового инференса.

**Содержание**

1. **Основы** — цикл предсказания токена и два кирпича: SwiGLU (вентиль и содержание) и RoPE
   (позиция как угол поворота).
2. **Анатомия** — attention изнутри, главный компромисс O(n²) prefill / O(n) memory-bound decode,
   спектр вариантов внимания (MHA → GQA → MQA → MLA → sliding window → linear/SSM), позиционные
   схемы и растяжение контекста через PI / NTK / YaRN.
3. **Два примера** — Granite 4.1 3B (40 слоёв, GQA 40:8) и Qwen3.8-27B (гибрид 3 × Gated DeltaNet
   + 1 × Gated Attention, повторённый 16 раз).
4. **Ресурсы и обучение** — честный подсчёт VRAM (веса + KV-кэш + буферы), таблица квантизаций
   от BF16 до Q3, pretrain / SFT / RL, chat template и tool calling как обычный текст.
5. **Развёртывание** — Transformers, vLLM / SGLang, llama.cpp / Ollama, managed API: пропускная
   способность, приватность, сложность эксплуатации.
6. **Как выбрать** — матрица решений и чек-лист того, чего не хватает между демо и продом.

**Тезисы, ради которых доклад делался**

- Планировать память нужно по формуле «веса + KV-кэш», а не по числу параметров. Наглядный
  контрпример из доклада: у 27B-гибрида кэш меньше, чем у 3B-модели (64 КБ против 80 КБ на токен),
  потому что в формулу входят только слои с полным вниманием, число KV-голов и размер головы —
  но не число параметров.
- Заявленные 131k / 262k токенов контекста — это потолок, а не рекомендация: память, время до
  первого токена и «потеря середины» платятся отдельно.
- Бенчмарки из карточки модели — маркетинговый материал: замеры вендорские, часть наборов
  внутренние, судья — тоже модель. Единственная надёжная процедура — свой оффлайн-тест.

## 2. От ReAct к своему harness

**Файл:** `harness-react-first.ppt` · доклад для разработчиков, знакомых с LLM API

Отправная точка: ReAct (Yao et al., 2022) сегодня — это пятнадцать строк цикла с tool calls.
Доклад про всё остальное — про обвязку, без которой этот цикл не доживает до репозитория.

**Содержание**

- **ReAct** — Thought / Action / Observation, почему это работало, и чего в цикле нет: ничего
  не сохраняется и ничего не ограничивается. Эти две нехватки задают два следующих блока.
- **Память** — три разные проблемы под одним словом (переполнение окна, потеря состояния при
  рестарте, изучение проекта заново каждую сессию). Разбор четырёх архитектурных подходов:
  Mem0 (пайплайн извлечения), LangMem (операции поверх Store), Letta (память как ОС),
  Graphiti (би-темпоральный граф) — с таблицей «чем платит каждый». Как это меряют
  (LoCoMo, LongMemEval) и почему длинный контекст ≠ память.
- **Guardrails** — lethal trifecta применительно к кодинг-агенту, пять уровней защиты от
  контентных фильтров до изоляции среды, инъекция через содержимое PR, защита по построению
  (Dual LLM, CaMeL, Progent) и HITL как отдельный слой с его подводными камнями.
- **Решение** — сборка харнесса: дизайн инструментов (ACI), проверки внутри кода инструмента,
  верификация как узел графа, топология с approval gate, карта «тезис → строчка кода» и честный
  список того, чего в демо нет.

**Тезисы, ради которых доклад делался**

- Цикл придумали в 2022 году, и он не изменился. Меняется обвязка: персистентность, политика,
  верификация.
- Промпт — не guardrail. «Не удаляй файлы» — пожелание; работают только уровни, которые нельзя
  обойти кодом модели: песочница, проверка пути до `resolve()`, `interrupt` перед необратимым.
- Верификация должна быть узлом графа, а не инструментом: инструмент агент может не вызвать,
  вызвать не так или проигнорировать результат.
- Ни одна из библиотек памяти не проектировалась под кодинг-агента. Для кода файловая система
  и git закрывают большую часть задачи.

В обоих докладах есть слайды со ссылками на первоисточники — статьи, документацию и бенчмарки.
